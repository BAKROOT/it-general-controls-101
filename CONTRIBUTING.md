# Contributing

Thanks for helping make **IT General Controls 101** better! This is a beginner knowledge base, so the most valuable contributions are the ones that make things *clearer*, not more advanced.

## Ways to help

- **Fix confusing wording.** If a sentence assumed knowledge a beginner wouldn't have, rewrite it or open an issue describing where you got lost.
- **Add or improve analogies.** Good real-world comparisons are gold here.
- **Correct inaccuracies.** ITGC practice varies by framework and firm; if something is wrong or misleading, please flag it with a source where possible.
- **Expand the glossary.** Every acronym should be defined on first use and listed in [glossary.md](glossary.md).
- **Improve templates and examples.** Real, usable artifacts help beginners the most.

## Ground rules

1. **Keep it beginner-friendly.** Define jargon on first use. Prefer short sentences and concrete examples.
2. **Keep the doc shape.** Each `docs/` chapter uses: *In plain English* → real-world analogy → *Why an auditor cares* → 2–4 concrete control examples → *Key terms* recap linking to the glossary.
3. **No professional advice.** This repo teaches concepts; it is not audit, legal, or accounting advice. Don't phrase content as formal guidance.
4. **Cite when you can.** For framework specifics (COSO, COBIT, SOX, NIST), link to primary sources.

## How to suggest an edit

1. Fork the repository and create a branch: `git checkout -b improve-change-management`.
2. Make your change in Markdown.
3. Open a pull request describing *what* you changed and *why it helps a beginner*.

Small PRs are easier to review and merge than big ones. Typo fixes are welcome any time.

## Style quick reference

- Files are Markdown (`.md`).
- Use sentence case for headings.
- Link related chapters and glossary terms generously.
- One idea per paragraph.
